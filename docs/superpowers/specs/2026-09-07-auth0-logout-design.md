# Auth0 Logout Design

## Goal

Make VEW logout terminate the browser's VEW/Amplify session, the Cognito user-pool session, and the Auth0 session. Logout must not request federated logout from any identity provider upstream of Auth0.

## Scope

This change targets the current public CloudFront deployment without a custom application domain. The existing frontend logout implementation remains unchanged to keep the patch small. Private/ALB deployments, custom domains, upstream identity-provider logout, and a dedicated logged-out page are outside scope.

## Current Behavior

The frontend calls Amplify `signOut({ global: true })` and then constructs a Cognito `/logout` URL. Cognito clears its own session and redirects to VEW's `/logout` path. Cognito does not clear an external OIDC provider's session, so the Auth0 SSO cookie survives and can authenticate the user again without prompting.

## Selected Approach

Use the existing configurable Cognito logout URL to chain Cognito logout into Auth0's `/v2/logout` endpoint:

```text
VEW logout
  -> Cognito /logout
  -> Auth0 /v2/logout
  -> https://<cloudfront-domain>/login
  -> fresh Cognito/Auth0 authorization request
```

The Auth0 request includes:

- `client_id=<Auth0 application client ID>` so Auth0 validates the return target against that application's configuration.
- `returnTo=https://<cloudfront-domain>/login` so the user returns to VEW's existing login entry point.
- No `federated` parameter, so Auth0 does not deliberately terminate an upstream enterprise or social-provider session.

Use `/v2/logout` instead of `/oidc/logout` because VEW receives Cognito tokens rather than Auth0's original ID token. Calling `/oidc/logout` without an Auth0 `id_token_hint` can introduce a logout-confirmation prompt. Capturing and retaining the upstream token solely for logout would add unnecessary state and security surface.

## Configuration

When OIDC is configured, `deploy.sh` will derive an environment `LogoutUrl` from the existing `OIDC_ISSUER_URL` and `OIDC_CLIENT_ID`. The URL will retain an `{appDns}` placeholder because the generated CloudFront domain is unavailable until CDK creates the distribution.

The public CDN construct will replace `{appDns}` with its generated `https://<distribution-domain>` URL and register the complete Auth0 logout URL in Cognito's allowed logout URLs. The stack already exports that value, and `frontend/web/configure_auth.sh` already places it in Amplify's `redirectSignOut` configuration.

When OIDC is not configured, the deployment script will not generate an Auth0 logout URL and the existing Cognito-only behavior will remain in place.

The Auth0 application must list the concrete URL below in **Allowed Logout URLs**:

```text
https://<cloudfront-domain>/login
```

This dashboard setting is a post-deployment operational step because the CloudFront domain is generated by AWS.

## Files

- Modify `deploy.sh` to construct and persist the Auth0 `LogoutUrl` only when OIDC is configured.
- Modify `frontend/infrastructure/cdk.json` to carry the generated development-environment value produced by the deployment configuration step.
- Modify `frontend/infrastructure/lib/constructs/app-cdn.ts` to resolve `{appDns}` against the CloudFront distribution domain without adding custom-domain behavior.
- Modify `frontend/infrastructure/test/infrastructure.test.ts` to cover the synthesized Cognito logout URL and the non-OIDC fallback.
- Create root-level `CHANGES.md`, beside `FINDINGS.md`, to document the code change, Auth0 Allowed Logout URLs step, expected session semantics, and verification procedure.

The following files will not change:

- `frontend/web/src/components/session-management/authenticator.ts`; its redundant explicit redirect remains as requested.
- `frontend/web/configure_auth.sh`; it already consumes the stack's logout URL output.
- `frontend/infrastructure/lib/constructs/app-user-pool.ts`; it already registers supplied logout URLs on the Cognito client.
- `frontend/infrastructure/lib/constructs/app-elb.ts`; private deployment is outside this change.
- Existing README files.

## URL Handling

Construct query parameters with URL-aware encoding rather than string concatenation where shell and TypeScript facilities permit. The final Cognito `logout_uri` must represent the complete Auth0 URL, while Auth0's `returnTo` value must resolve to the CloudFront `/login` URL exactly. Tests will assert the synthesized structure so double encoding or a missing scheme cannot silently ship.

## Error Behavior

If Auth0 rejects the logout request, it will display an Auth0 error page. The operational documentation will identify the usual causes: the wrong Auth0 client ID or a `/login` URL that does not match the application's Allowed Logout URLs.

The implementation will not fall back to silently skipping Auth0 logout, because that recreates the original false-logout behavior.

## Testing

Infrastructure tests will verify that:

1. An OIDC deployment registers a Cognito logout URL pointing to the configured Auth0 tenant.
2. The Auth0 logout URL contains the Auth0 client ID.
3. Its `returnTo` value resolves to the generated CloudFront domain's `/login` path.
4. A deployment without OIDC does not generate an Auth0 logout URL.

After deployment, manual verification will confirm:

1. Signing out removes the VEW session and passes through Cognito and Auth0 logout endpoints.
2. Returning to login requires a new Auth0 authentication when Auth0 is the credential source.
3. The flow does not contain `federated`.
4. Invalid or absent Auth0 Allowed Logout URL configuration produces a documented, diagnosable Auth0 error rather than a redirect loop.
